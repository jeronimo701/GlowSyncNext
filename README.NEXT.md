# Архив: GlowSync Next 0.2.0 — первая тестовая сборка

Текущая версия — 0.3.0. Эта страница сохранена как история первого этапа; актуальные возможности и ограничения: [GUIDE.ru.md](GUIDE.ru.md).

Основа: skybots-tg/glowsync, коммит f5e2ed6bbcefff10fdf7b1b544393d5b444b0d1e. MIT; исходная лицензия и авторство сохранены.

## Реализовано

- Профили Обычная подсветка / Игра / Кино / Музыка. Собственные режим, яркость, статичный цвет, FPS, сглаживание, гамма, насыщенность, глубина, размытие, порог чёрного и настройка полос для каждого.
- Автовыбор по приложению на переднем плане, опрос каждые 400 мс. Приложения в фоне не перехватывают профиль. Собственное окно настроек сохраняет предыдущий профиль.
- Кандидат должен оставаться стабильным 800 мс по умолчанию (настраивается 200–5000). Обычно реакция занимает примерно 0.8–1.2 с.
- Игры распознаются по каталогам steamapps/common, Epic Games, [Games]. Для остальных — правила по точному имени .exe.
- Видеоплееры: VLC, mpv/mpvnet, MPC-HC/BE, PotPlayer, wmplayer.exe, Kodi, Plex, SMPlayer.
- Аудиоплееры: Spotify, AIMP, foobar2000, MusicBee, Winamp, Tidal, Deezer, YandexMusic, AppleMusic.
- Браузеры: Chrome/Edge/Firefox/Brave/Opera/Vivaldi и производные. Windows Accessibility читает доступную адресную строку активного браузера, не содержимое страницы, формы, cookies или историю. Адреса/заголовки не записываются в журнал. Зависший провайдер не блокирует движок и UI.
- YouTube, youtu.be, Vimeo, Twitch, Netflix, Кинопоиск → Кино; YouTube Music → Музыка. Для YouTube есть резервное распознавание по суффиксу заголовка.
- Правила: имя .exe + необязательный фрагмент заголовка; первое совпадение выше встроенного распознавания. Добавление/удаление и включение правил в интерфейсе.
- Принудительный профиль или полностью ручной режим. Выбор режима на Главной отключает автоматику до повторного выбора «Автоматически».
- Исправление рассинхронизации 65/81: стороны — источник истины, устаревшие координаты пересоздаются при загрузке и изменении, даже без окна настроек.
- Skydimo и классический Adalight, все шесть порядков каналов RGB.
- WLED/DDP: явный IP, UDP 4048, фрагментация по 1440 байт, PUSH на последнем пакете. Транспорт Serial/DDP и кодирование кадров отделены от движка.
- UART-бюджет с запасом 10% и отправка последнего кадра: для 81 LED при 115200 бод максимум около 41.6 FPS. Старая очередь не накапливается.
- Отдельные приложение, singleton, конфиг и запись автозапуска GlowSyncNext. По умолчанию автозапуск выключен.
- Исходные атомарное сохранение с .bak и latest-frame-only сохранены, они уже были в оригинале.

## Запуск

Windows 10/11 x64 и .NET 8 Desktop Runtime. Запустить GlowSync.Next.exe. Перед подключением к USB-ленте закрыть GlowSync/Skydimo/HyperHDR, если они занимают тот же COM-порт.

Настройки: `%LOCALAPPDATA%\GlowSyncNext\config.json`, журнал рядом в `logs`. При первом запуске Next читает старый `%LOCALAPPDATA%\GlowSync\config.json` и сохраняет отдельную копию. Оригинал не изменяется. При отсутствии старого конфига используется исходный импорт Skydimo, если он доступен.

На Главной выбрать «Автоматически». В «Профили и автоматика» настроить пресеты и правила. Строка состояния показывает профиль, причину и процесс. Монитор выбирается на странице «Экран» для всех профилей; баланс белого, ночной режим и музыкальные эффекты общие. Главная регулирует яркость активного профиля; настройки страницы «Экран» применяются к режиму «Вручную».

Для SKA127 с физической раскладкой пользователя: 20 слева, 41 сверху, 20 справа, 0 снизу; всего 81. Начало и направление зависят от монтажа. «Тест сторон»: красный слева, зелёный сверху, синий справа, первый LED белый, последний фиолетовый. По имени модели физическая раскладка автоматически не меняется.

Adalight: вручную выбрать COM, число LED и скорость, поддерживаемую прошивкой. WLED: выбрать WLED/DDP, указать IP, порт 4048 и число LED. COM и baud для DDP не используются. Порядок каналов WLED обычно RGB; физический GRB настраивается в WLED.

DDP не подтверждает получение: статус «подключён» означает готовность отправителя, а не доказанную доступность контроллера.

## План проверки на ленте

1. Один цвет и тест сторон: все 81 LED работают, стороны совпадают.
2. Авто: игра → Игра; видеоплеер → Кино; возврат в игру → Игра.
3. Браузер: обычная вкладка → Обычная подсветка; YouTube → Кино; YouTube Music → Музыка.
4. Аудиоплеер → Музыка. Плеер в фоне не меняет профиль игры.
5. Быстрый Alt+Tab меньше 800 мс не переключает профиль.
6. Закрепить Кино вручную: смена приложения ничего не меняет. Вернуть Авто.
7. Добавить правило .exe и проверить его приоритет, удаление и сохранение после перезапуска.
8. Проверить отключение USB, сон, Win+L, смену разрешения/HDR, Alt+Tab.

## Ограничения и следующие этапы

- Пока определяется сайт/приложение, а не воспроизведение. Пауза на YouTube остаётся Кино; VLC с аудиофайлом тоже Кино, если не добавить правило. Playback-aware распознавание через Windows Media Sessions — следующий этап.
- Доступность адресной строки зависит от браузера, локализации, полноэкранного режима. Для других видеосайтов при недоступном адресе может потребоваться правило по заголовку.
- Новые UWP-плееры под ApplicationFrameHost требуют правил; повышенные/защищённые процессы могут скрывать путь.
- DRM-видео может быть чёрным в захвате. Кино-профиль не снимает это ограничение.
- Захват и HDR унаследованы от оригинала. Новый собственный HDR-конвейер и измерение общей задержки ещё не реализованы.
- Один контроллер за раз. TPM2.NET/OPC/Art-Net, несколько контроллеров и готовые прошивки Arduino/ESP32 — последующие этапы.
- Произвольный массив `layout.leds` заменяется картой по сторонам. Редактор произвольной геометрии ещё не добавлен.
- USB-контроллеры и реальный WLED в этой среде не проверялись. Проверены форматы пакетов, локальная UDP-передача, классификатор, конфиг и реальный DXGI-захват. Стабильность в играх/кино/HDR требует проверки на железе пользователя.

## Сборка и тесты

.NET 8 SDK:

```powershell
dotnet build GlowSync.sln -c Release
$env:GLOWSYNC_NEXT_DATA_DIR = Join-Path $PWD 'artifacts\test-config'
dotnet run --project tests -c Release
dotnet run --project tests -c Release -- --ui-smoke
Remove-Item Env:\GLOWSYNC_NEXT_DATA_DIR
dotnet publish src\GlowSync.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -p:DebugType=none -o artifacts\publish
```

Тесты: регрессии 65/81, подписки на правила, сериализация, приложения/YouTube/поддельные домены, debounce, Skydimo/Adalight, перестановка RGB, UART-бюджет, DDP через UDP loopback с восстановлением 1000 LED из трёх пакетов. UI-smoke создаёт и отрисовывает окно без запуска устройства и потоков захвата. Некоторые исходные проверки пропускаются без установленного Skydimo.

Технические источники DDP: https://kno.wled.ge/interfaces/ddp/ и https://www.3waylabs.com/ddp/ .
