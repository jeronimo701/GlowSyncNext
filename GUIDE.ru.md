# GlowSync Next 0.3.3 — инструкция

В «Эффекты и музыка» → «Дыхание» добавлена явная галочка «Менять цвет при каждом вдохе». Включено — каждый новый цикл получает другой оттенок; выключено — меняется только яркость выбранного цвета. Это общая настройка эффекта для всех профилей.

Fire Lamp / EmbUI и WLED — не взаимозаменяемые прошивки. Прежде чем выбирать WLED/DDP для сетевой матрицы, проверьте её фактическую прошивку, поддерживаемый протокол и число LED; внешний вид матрицы не подтверждает совместимость.

Тестовая версия для Windows 10 2004 (19041) и новее, Windows 11, x64. Обычной сборке нужен .NET 8 Desktop Runtime; вариант selfcontained включает его. Основа — skybots-tg/glowsync, лицензия и авторство оригинала сохранены.

## Начало проверки на SKA127

1. Полностью закройте другие программы управления той же лентой: GlowSync/Skydimo/HyperHDR.
2. Запустите GlowSync.Next.exe. Настройки Next: `%LOCALAPPDATA%\GlowSyncNext`. Оригинальный `%LOCALAPPDATA%\GlowSync` не изменяется.
   При обновлении существующего конфига версии 1/2 создаётся отдельный файл `config.json.v1-before-v3.bak` (или v2), который не перезаписывается следующими сохранениями.
3. Лента и устройство: Skydimo, COM3 или Автоматически, 115200 бод. Для физической раскладки пользователя: 20 слева, 41 сверху, 20 справа, 0 снизу. Итого 81.
4. Тест сторон: слева красный, сверху зелёный, справа синий, первый LED белый, последний фиолетовый. Поправьте начало/направление/сдвиг по физическому монтажу.
5. Для переключения по своим правилам: Главная → Профиль → Полуавтоматика (по правилам).

## Полуавтоматика и правила

Встроенное распознавание YouTube, сайтов, игр по каталогам и плееров удалено. Адресная строка и медиасессии Windows не опрашиваются. Переключение происходит только по включённому правилу для процесса на переднем плане. Нет совпадения → профиль «Обычная подсветка». Первое подходящее включённое правило имеет приоритет.

На первом запуске 0.3.2 добавляются выключенные примеры: YouTube/YouTube Music для Vivaldi, Chrome, Edge и Firefox, Twitch для Vivaldi, видеоплееры, аудиоплееры и game.exe. Старые пользовательские правила сохраняются выше примеров. Примеры не дублируются при перезапуске; удалённые не появляются заново. Включайте только нужные галочки «Вкл.» в таблице. Это галочки конкретных правил, а не скрытого распознавания. Для YouTube Music включите отдельную строку выше общей YouTube. Если заголовок окна не содержит указанного текста, правило не сработает. Если слово встречается на другой странице, правило тоже совпадёт — это обычный поиск фрагмента, без анализа сайта. Пауза не учитывается.

«Добавить правило» открывает выбор запущенного процесса с обновляемым списком. Можно выбрать EXE с диска или ввести имя вручную. Затем задайте профиль и необязательный фрагмент заголовка. Подтверждённое правило добавляется включённым; отмена ничего не добавляет. «Выше»/«Ниже» меняют приоритет. Имя процесса сопоставляется точно, без учёта регистра и суффикса .exe; заголовок — поиск подстроки без учёта регистра.

Кнопка «Включить полуавтоматику по правилам» сразу меняет режим и надпись состояния. Повторное нажатие выключает полуавтоматику. Если активное приложение ещё не известно, показывается обычная подсветка и предложение перейти в нужное приложение. По умолчанию кандидат удерживается 800 мс, опрос каждые 400 мс. В собственном окне настроек сохраняется предыдущий профиль. Выбор режима на Главной отключает полуавтоматику. Сама кнопка режима не включает глобально выключенную ленту.

Ручной выбор профиля закрепляет его. Выбор режима на Главной переводит в ручное управление. Возвращение к автоматике — через список профилей или кнопку на странице профилей. Яркость на Главной, постоянный цвет на странице эффектов и параметры страницы «Экран» относятся к активному профилю. В ручном режиме они меняют ручные значения. Дублирующие поля в профиле и на странице «Экран» синхронизированы в обе стороны; неактивные профили не меняются. Монитор и HDR общие, как и баланс белого, ночной режим, музыкальный стиль и параметры анимаций. Ночной режим может ограничить яркость ниже значения профиля. В тесте сторон/белого действует тестовый источник, а не выбранный режим.

## 60 FPS и UART

Один RGB-кадр на 81 LED: 6 + 81 × 3 = 249 байт. UART 8N1 передаёт 10 бит на байт. При 115200 бод кадр занимает 21,61 мс; физический предел потока ~46,27 FPS, безопасный программный лимит с 10% запасом ~41,64 FPS. Настройка 60 FPS не отменяет этот предел.

При 230400 бод пропускной способности достаточно для 60 FPS. Но контроллер тоже должен поддерживать эту скорость: смена baud только в приложении может полностью отключить подсветку. Для SKA127 поддержка повышенной скорости пока не подтверждена. Не менять протокол/число LED ради показателя FPS. Сетевые выходы не ограничены UART.

В 0.3.1 интервал отправки считается от начала записи, без повторного добавления её длительности; высокоточный таймер и запланированные сроки уменьшают накопление погрешности ожиданий. Старые кадры не догоняются очередью. На Диагностике сравните запрошенный/безопасный лимит, обработку, новые кадры и отправку. 60 отправок в секунду не означают 60 разных кадров видео или подтверждённые 60 обновлений физических LED.

## Диагностика

Страница показывает новые кадры экрана, рассчитанные кадры, успешные записи каждого выхода, среднее/p95 времени обработки, ожидание кадра, ошибки и подключения. На статичной картинке новых кадров может быть мало — это нормально.

Время записи — время вызова драйвера/сокета. UART-время вычислено из количества байт и baud. Эти величины не являются полной задержкой до свечения LED; её нужно измерять физически. Старые кадры заменяются свежими, а не накапливаются.

Кнопка сохраняет JSON в `%LOCALAPPDATA%\GlowSyncNext\diagnostics`. В JSON не включаются URL, заголовки окон, IP, COM-порты, серийные номера и пути к приложениям. Программное время обработки не включает аппаратную обработку контроллером/лентой.

## Контроллеры

| Протокол | Подключение | Типичный порт | Особенности |
|---|---|---|---|
| Skydimo | USB/COM | 115200 бод | Модель определяет число LED |
| Adalight | USB/COM вручную | По прошивке | Количество LED и скорость должны совпасть |
| WLED/DDP | UDP на IP | 4048 | RGB, PUSH последнего пакета, без подтверждения |
| TPM2.NET | UDP на IP | 65506 | Равные блоки, дополнение нулями |
| OPC | TCP на IP | 7890 | Канал 0–255, команда Set Pixels |

При смене протокола в интерфейсе подставляется типичный сетевой порт; затем можно указать свой. Для сетевых протоколов baud/COM не используются. UDP-статус означает готовность отправителя, не доказанную доставку. Для WLED порядок обычно RGB; физический GRB задаётся в настройках WLED.

## Несколько выходов

«Доп. контроллеры» позволяет добавить до восьми выходов. Сначала заполните параметры, затем включите. «Начало» — индекс с нуля в общей карте, «LED» — сколько цветов взять. Например 0/20 передаст первые 20 LED, 20/41 — следующие 41. Недостающий участок заполняется чёрным. Цветокоррекция и экранная геометрия общие.

У каждого выхода свой поток, переподключение и очередь последнего кадра. Быстрый сетевой выход может получать 60 FPS одновременно с медленным USB. Общий движок рассчитывает кадры под самый быстрый активный выход. Дублирующие адреса/порты не запускаются. При нескольких USB-выходах укажите COM основного вручную. Причины отказа и состояние выходов видны в Диагностике.

Если основной контроллер не нужен, выключите соответствующий флажок. При удалении/выключении выхода программа отправляет чёрный кадр и закрывает соединение. Несколько сконфигурированных адресов не означают проверку совместимости реального железа.

## Произвольная геометрия

На странице дополнительных контроллеров есть сохранение/загрузка карты JSON. Минимальный пример:

```json
{
  "gridWidth": 10,
  "gridHeight": 10,
  "useCustomMap": true,
  "leds": [{"x": 0, "y": 9}, {"x": 0, "y": 5}, {"x": 0, "y": 0}]
}
```

Координаты — клетки сетки, порядок — порядок физических LED. Верхний левый угол (0,0). Размеры 1–1000; 1–1000 LED; координаты внутри сетки. Импорт проверяется до применения. В этом режиме поля сторон/начала/сдвига не перестраивают карту. Кнопка «Карта по сторонам» возвращает генератор.

## HDR

В «Профили и автоматика» раскройте HDR. Режим экспериментальный, по умолчанию выключен. На HDR-выходе запрашивается FP16/scRGB, кадр уменьшается на GPU, после чего яркость переводится через extended Reinhard в SDR/sRGB для ленты. SDR продолжает использовать 8-битный захват.

Белый по умолчанию 203 нит, пик 1000 нит. Подберите значения по монитору/контенту и сравните с выключенным режимом. Реальный формат виден в Диагностике: R16G16B16A16_Float означает FP16, B8G8R8A8_UNorm — 8 бит. Математика и формат преобразования проверены тестами; визуальная точность на HDR-железе ещё не подтверждена. Цвета за пределами sRGB обрезаются; широкогамутный gamut mapping не реализован. DRM-захват не обходится.

## Сборка, прошивки и GitHub

Приложение: `./build.ps1` (.NET 8 SDK). Для среды без рабочего стола: `./build.ps1 -Headless`. Параметр `-SelfContained` включает runtime. Результат в artifacts/release. Исходный install.ps1 устанавливает только Next.

Движок выделен в engine/GlowSync.Engine.csproj без зависимости от WPF: захват, обработка, конфиг и устройства. Окно настроек, системные события, медиасессии и автоматический выбор профиля связывает Windows-хост в src/GlowSync.csproj. Один исходный файл включается только в одну сборку.

Прошивки Arduino Uno/классического ESP32 и схема: firmware/README.ru.md. Они собраны компиляторами, но не проверены на подключённых платах.

В .github/workflows/build.yml подготовлены сборка приложения, тесты, прошивки и артефакты. Ручной запуск workflow с draft_release=true и существующим тегом создаёт только черновик релиза. Автоматической публичной публикации нет. Workflow на GitHub пока не запускался — репозиторий пользователя ещё не подключён.

## Что остаётся проверить физически

- Все 81 LED, совпадение сторон, перезапуск и сохранение настроек.
- Игры: Alt+Tab, полноэкранный режим, смена разрешения и HDR.
- Кино: полосы, субтитры, тёмные сцены, реальные цвета HDR.
- Сон, Win+L, выключение монитора, отключение USB, занятый COM.
- Реальные Adalight/WLED/TPM2/OPC и несколько устройств одновременно.
- Полная задержка от картинки до света и корректность питания/сигнала самодельных плат.
